# J.A.R.V.I.S · сервер воронки (Railway)

Рухає воронку «Monoclo · Свій принт» у KeyCRM цілодобово, без відкритої вкладки.

Кожні 10 хвилин:
1. синхронізує картки воронки (публічний API KeyCRM);
2. читає переписку кожної відкритої картки від імені технічного користувача;
3. рухає етапи за відповідями менеджерів (ціна, ескіз, рахунок, оплата), додає товар із каталогу;
4. бачить причини відмов («дорого», «розмір», «подумаю», «ні, дякую»);
5. переводить у «Нагадування» тих, хто мовчить понад добу після нашої відповіді;
6. шле в Telegram кнопки «Закрити: …» / «Оплачено» / «Лишити» і список «Нагадати сьогодні».

О 09:30 (BRIEF_TIME) — ранковий блок воронки з конверсією.

Кожні 3 хвилини в робочий час (10:00–20:00) — перевірка карток, де клієнт чекає відповіді: понад 15 хв (SPEED_ALERT_MINUTES) → сповіщення «⏱ … чекає відповіді N хв».

Нагадування після ціни йдуть по черзі у двох варіантах (A «ескіз сьогодні», B «частини monobank + відгуки»); текст приходить у Telegram, натиснути — скопіюється. Сервер рахує, після якого варіанта клієнт дійшов до ескізу.

Обіцянки клієнтам: сервер бачить у відправлених повідомленнях менеджерів фрази на кшталт «уточню завтра на виробництві», «завтра повернуся з варіантами ескізу» (`promises.js`, спільний з розширенням). Обіцянки на сьогодні йдуть у ранковий блок, а о 18:00 (PROMISE_TIME) приходить список тих, на які ще ніхто не відповів, з кнопками «✅ виконано» / «⏭ на завтра». Відповідь менеджера в тому ж чаті щонайменше через 3 години після обіцянки закриває її автоматично.

Картки для клієнтів, що пишуть знову (`newcards.js`): KeyCRM сама створює картку лише новому контакту. Якщо клієнт каналу Monoclo пише ще раз, останнє повідомлення від нього, відкритої картки немає і за 7 днів (AUTO_CARDS_AFTER_CLOSE_DAYS) жодну його картку не закривали, сервер створює картку «Чат з …» на етапі «Новий», прив'язану до покупця, і пише в Telegram «🆕 Нові картки». Минуле не чіпає: лише повідомлення після першого запуску. Не більше 10 карток за цикл (AUTO_CARDS_MAX). Канали Monoclo визначає за назвою (MONOCLO_CHANNEL_RE, за замовчуванням `mono`). Вимкнути: AUTO_CARDS=off. Діагностика: поле `autoCards` у JSON стану і рядок `auto-cards` у логах.

Щопонеділка о 10:00 (WEEKLY_TIME) — тижневий звіт: нові звернення, переходи, втрати й причини, гроші в роботі, завислі, швидкість відповіді по менеджерах, результати A/B.

## Налаштування в Railway
1. New Project → Deploy from GitHub → цей репозиторій.
2. Variables: скопіювати з `.env.example` і заповнити.
3. Settings → Volumes → Add Volume, mount path `/data` (там зберігається стан воронки).
4. Перевірка: відкрити домен сервісу (Settings → Networking → Generate Domain) — JSON зі станом останнього циклу.

## Технічний користувач KeyCRM
- KeyCRM → Налаштування → Користувачі → додати користувача, напр. «J.A.R.V.I.S».
- Роль з доступом до воронок і чатів Monoclo, без доступу до фінансів і налаштувань.
- Двофакторну перевірку для нього не вмикати.
- Сесія оновлюється сама; якщо вхід зламається, сервер напише в Telegram.

## Після запуску
У розширенні: Налаштування → Автоматика → «Воронкою керує сервер на Railway» — увімкнути,
щоб розширення не дублювало таймери.

## Оновлення логіки
`funnel.js` і `promises.js` — копії з розширення. Після змін у розширенні: `npm run sync` і push.
